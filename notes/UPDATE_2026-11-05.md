# FIELD ALIGN 更新メモ（2026-11-05・Claude）

## 追加した機能：登記所備付地図データ（法務省地図XML）の取り込み

画面左の「4 登記所備付地図データ（地番図）」から使う。

1. G空間情報センターのZIP（例：`11347-0304-2026.zip`）をそのまま選ぶ。内側のZIP1個、XML1個を選んでもよい。
2. まとめZIPの場合は、図面一覧と地番索引（search-list.csv）だけを先に読む。「大字ごとに読み込む」か「ZIP内の地番を探す」で、必要な図面だけを展開・解析する（吉見町のXMLは全部で約918MBあるため）。
3. 公共座標の図面は、そのまま正しい位置に描画する（平面直角座標1〜19系 → 緯度経度、国土地理院の計算式）。
4. 任意座標の図面は「仮配置」（オレンジの点線）で置く。同じ大字の公共座標の図面があればその付近、無ければ地図の中心に置く。
5. 「位置合わせ」で目印を指定する：図面上の角をタップ（近くの頂点に自動で吸い付く）→ 航空写真の同じ場所をタップ。
   - 1点：平行移動だけ
   - 2点：回転・縮尺も
   - 3点以上：最小二乗で合わせ、残差（m）を表示する
   - 範囲は「図面全体」か「図郭1枚ずつ」を選べる（旧公図はゆがみがあるので、図郭ごとのほうが精度が出る）
6. 位置合わせの結果は端末内（IndexedDB）に保存する。再読み込みしても残る。
7. 地番検索で筆に移動し、ポップアップの「この筆を対象地にする」で既存の対象地・所在地欄に反映する。
8. 「位置合わせ結果を出力（GeoJSON）」：公共座標の筆と位置合わせ済みの筆を出力する（仮配置の筆は出力しない）。スキーマは `moj-parcels/v1`。地番図アプリへの取り込み用。

## 保存データ

- IndexedDB `kozu-align` version 2
  - `records`：従来どおり（公図照合の履歴）
  - `mojmaps`（新規、keyPath `key` = `市区町村コード|地図名|ZIP内ファイル名`）：解析済みの筆（任意座標・公共座標の値のまま）、図郭、位置合わせ `transforms: { all, sheets: { 図郭番号: … } }`
- 変換パラメータ：`{ center:[緯度,経度], angle:度（時計回り正）, scale, anchor:[X,Y], pairs:[{src:[X,Y], dst:[緯度,経度]}], rms }`
  - 地図XMLの座標は X＝北、Y＝東（m）。任意座標でも同じ向き。

## 確認したこと

- 吉見町の実データで解析を検証（Node.js）：128図面のうち任意座標124・公共座標4、地番92,445筆。長谷Ｂ（4,287筆）の解析は約0.7秒。全筆のリングが閉じ、各筆が1つの図郭に属することを確認。
- 座標変換：1903番の位置が別計算（Python）と一致、国土地理院の逆ジオコーダで「吉見町大字長谷」を確認。目印フィットは既知の変換を0.4mm以内で復元。
- ヘッドレスChromeで通しテスト：ZIP読み込み→大字長谷の3図面を読み込み→地番検索→対象地に設定→3点で位置合わせ→保存→再読み込みで復元→GeoJSON出力→既存の履歴ダイアログ。コンソールエラーなし。スマホ幅の表示も確認。
